## sxPanel v0.8.0-Beta

**In-game menu redesign**
The in-game menu has a new dark, solid look with hairline borders, outlined icons and a single continuous panel that joins the page tabs and the main menu card. Heavy blur effects are gone, so it renders consistently in the game's embedded browser.

- Main menu items are grouped into **Player**, **World** and **Server** sections, with icon badges and value pills for settings you cycle through.
- Player cards, the player modal and the reports tab now size to their content instead of leaving empty space.
- Health is shown as a bar, and status indicators are clearer.

**Server statistics page**
A new Stats page in the in-game menu shows server uptime, player count and resource status at a glance.

**In-game Resources page**
A new Resources tab in the in-game menu lists every resource and lets you start, stop, restart and ensure them without leaving the game. It requires the `commands.resources` permission. Stop, restart and ensure on a running resource ask for confirmation first, and the action buttons have tooltips.

**Resource config editor**
Edit a resource's config files directly from the web panel Resources page or the in-game Resources page.

- Requires both `server.cfg.editor` and `commands.resources`.
- Editing is confined to the resource's own folder; path traversal, absolute paths and links are rejected.
- Only config-like files are editable: names containing a common config word (config, cfg, settings, options, locale, lang, translations, ...) or files in a conventional config, locale or data folder.
- Files are capped at 256 KiB, a `.bkp` backup is kept, and every save is written to the admin action log.

**Built-in chat commands**
Every `/tx` menu action is now available as a chat command by default. The Custom Commands page shows each built-in command and its status. A custom command with the same name takes over, and creating a disabled custom command with that name turns the built-in one off.

**FiveM Enhanced (gen9) support - experimental**
Initial compatibility with FiveM Enhanced / FXServer gen9.

- Releases now ship two archives built from the same source: `monitor.zip` for gen8 and `txadmin.zip` for gen9. Use the one that matches your server.
- sxPanel detects the gen9 runtime, starts the `cfx-server` binary there, and works under either resource name (`monitor` or `txadmin`).
- The version and resource path no longer depend on natives that are unreliable during gen9 boot.
- The deployer uses the v5 recipes index on gen9.

Gen9 support is new and has had limited testing. Please report any problems you hit.

**Cfx Steam OAuth changes**
Cfx moved Steam identifiers to OAuth account linking on 2026-11-04, so `steam_webApiKey` no longer has any effect.

- The deployer no longer asks for a Steam Web API key on recipes that require Steam.
- Generated `server.cfg` files set `sv_enforceSteamAuth` (FXServer 38004+) for those recipes, unless the recipe already sets it.

**Player renames**
Name changes made with the `SET_PLAYER_NAME` native now reach the panel playerlist, the in-game menu, the player database, name history and the server log.

**Deployer**
More official framework recipes in the picker, on top of what the citizenfx index lists:

- FiveM: QBCore, ox_core, ND Core, and Kora Framework (alpha - the recipe is still under construction upstream).
- RedM: RSG Core, TPZ-CORE, RedEM:RP, RPX Framework and QBR Core.

These extras are hidden on gen9 builds, and an upstream entry with the same URL takes precedence.

**Fixes**

- The in-game menu no longer crashes when a player's details time out or fail to load; the error is shown in the player modal instead.
- Bringing a player now handles routing buckets correctly, so the player is visible to the admin when moved between instances.
- Menu requests no longer hang when an error occurs on the game side.
- Empty lists coming from the game no longer cause errors in the menu.
- The server name falls back to `txAdmin-serverName` when `sv_projectname` is unset.
- The menu's WebGL effects are released after a period of inactivity and rebuilt on demand, and recover if the graphics context is lost, avoiding Chromium's limit on active WebGL contexts.
- The web panel no longer hammers the backend with repeated requests from some pages.
- Restarting the monitor resource manually is handled gracefully.
- Fixed panel layout sizing for the collapsed playerlist sidebar and the dashboard.

**Housekeeping**

- The in-game menu's error screen now includes the component stack, making in-game problems easier to diagnose.
- Fixed a build script issue that could corrupt the resource manifest during concurrent file operations.
- Patch-level dependency updates.
- The CI secret scan now uses the open-source gitleaks CLI.
